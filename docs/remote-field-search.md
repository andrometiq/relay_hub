# Link and multiselect search

Record-backed fields use the Fusion interaction pattern: focus loads a bounded suggestion page, typing waits 300 ms before an API request, and choosing a result commits its ID. There is no record-directory preload. New input, blur, changed field context, and unmount cancel pending work; generation checks prevent stale responses from replacing newer results. Keyboard arrows/Enter select, Escape dismisses, and chips preserve selected values across searches.

The shared `ChoiceField` accepts a `field.search(query, signal)` callback. Core `RemoteLinkField` adapts a permission-scoped `field.method`, optional `field.kind`, and `field.params`; Link and MultiSelect fields automatically use that adapter when a method is provided. Results contain `{value, label}`, with a maximum of 30 displayed suggestions. Narrow the query for additional matches. Selected existing IDs remain visible even when absent from the current results. Fixed enums such as channel types remain local.

Installed Core usage: team members, conversation team/agent assignments, ticket/case assignees, business records, new-conversation contacts, and existing automation/flow/learning references. These use their existing permission-checked and bounded endpoints. Case assignee search now forwards the query while retaining contact-access checks. Team user results are capped at 30.

Hub token/account-access fields use GET `/auth/options?kind=grants|accounts&query=...`. Accounts are administrator-only; grants belong to the authenticated user. Account IDs use indexed bytewise prefix ranges, capped at 30 plus one lookahead row. Migration 0025 adds the matching account and user-grant indexes. Security page responses no longer embed complete account or grant lists. Grant writes validate the exact account in the database.

Validation: Core cases and collaboration database integrations passed. Hub authentication database suite passed under Go race detection, including result bounds, search beyond the first page, role isolation, revocation, literal wildcard handling, and dynamic account grant validation. Browser fixtures verified no search on mount, debounce, stale-response rejection, keyboard selection, retained multiselection, and mobile width. Hub browser requests were intercepted; these checks did not create accounts or tokens. Installed Core/Hub frontend builds passed.

Scale evidence is recorded separately. Bounded payloads prevent browser directory downloads; they do not establish search latency for two million records in every Core business DocType. Core searches still depend on each DocType's database indexes and permission filters.

Hub scale check: `RELAY_TEST_OPTIONS_SCALE=2000000 go test -race ./internal/auth -run ^TestRemoteOptionsBoundedAndScoped$ -count=1 -v` passed in an isolated PostgreSQL schema. After inserting 2,000,000 synthetic accounts, the combined lookup/permission checks took 45.997 ms; full test setup and execution took 44.50 seconds. This measures local handler/database behavior, not end-to-end browser latency or Core DocType searches. The test removed its schema on completion. Evidence: Hub `.runtime/remote-search-scale.log`.
